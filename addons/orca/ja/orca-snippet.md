## Orca 連携(flightwake アドオン)

Orca の中で作業していて、別の agent に相談やレビューを頼むとき:
- ユーザーが既に開いている見える Orca タブにメッセージを送り、そのタブから返信を読む。背景プロセス(例:`codex exec`)は起動しない——ユーザーから見えない。
- 適したタブが無い?まずユーザーに伝えて聞く。自分の判断で背景実行に切り替えない。
- Orca のコマンドはバージョンで変わる:記憶した構文に頼らず、`orca skills get orca-cli` で現行版のガイドを読む。

書き手は一人(Stop hook はどのベンダーのセッションでも締めを促す。書き手を決めないと両側が同時に STATE を書き換える):
- 相談やレビューに呼ばれた agent は record を書かず、STATE も変えない。結論を呼んだ側の agent に返す。
- レビューを頼んだ agent が、採用した結論を自分の record に書く。
- レビュアーは読むだけで変更しない——レビュー依頼に明記する(見えるタブに読み取り専用の制限があるとは限らない)。変更はメインラインの agent が行い、すべての変更を同じ側の記録に残す。

レビュー依頼では、返信に 4 項目を求める:結論;根拠(ファイルと行番号);検証していない部分;検討したが採らなかったやり方。
決定に影響するレビュー返信は、原文を repo 内のファイルに保存する(`docs/plans/<テーマ>.review-<レビュアー>.md` に倣う):端末の画面は残らず、メインラインに届くのはレビュアーの最終結論だけで、過程は届かない。
