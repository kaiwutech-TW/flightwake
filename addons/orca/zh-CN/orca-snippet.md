## Orca 协作(flightwake 附加组件)

在 Orca 里工作、要找另一个 agent 讨论或审查时:
- 把消息送进用户已打开的可见 Orca 分页,再从该分页读回复。不要另起后台进程(例如 `codex exec`)——用户看不到。
- 找不到合适的现有分页?先告诉用户、问他。不要自行决定改走后台。
- Orca 的命令会随版本变动:不要凭记忆写语法——用 `orca skills get orca-cli` 读当前版本的说明。

只有一个写手(Stop hook 在每个厂牌的 session 都会催收尾;不讲清楚谁是写手,两边会同时改 STATE):
- 被找来讨论或审查的 agent 不写 record、不改 STATE,把结论交回给找它的 agent。
- 找人审查的 agent 负责把采纳的结论写进自己的 record。
- 审查者只读不改——审查请求里要明讲(可见分页不一定有只读限制)。要改由主线 agent 改,让所有变更都留在同一边的记录。

请对方审查时,要求回复包含四项:结论;依据(文件与行号);没有验证的部分;考虑过但不采用的做法。
会影响决策的审查回复,原文存成 repo 里的文件(比照 `docs/plans/<主题>.review-<审查者>.md`):终端画面不会留存,主线也只拿得到审查者的最终结论,拿不到过程。
