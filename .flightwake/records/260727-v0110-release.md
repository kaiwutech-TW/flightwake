**TL;DR**:接續 [[260727-four-language-install]] 與 [[260727-oss-pr-flow-hardening]]。使用者要求把擱置的 0.10.1 與本日這批一起出。判定為 **minor 而非 patch**(這批加了功能不只修錯),發 v0.11.0。GitHub Release 觸發 release.yml,OIDC 發布成功,`npm audit signatures` 驗證通過,並從 npm 端到端實裝日文版確認無誤。第七次 Release,仍零失誤。

## 關鍵發現

1. **版本號的判斷點不在「上次留下什麼號碼」而在「這批做了什麼」**:package.json 停在 0.10.1(2026-07-23 bump 未發),照字面接續會出 0.10.1,但四語安裝內容與新 CLI 行為是 feature,semver 上該進 minor。npm 版本一旦發布無法回收(72 小時後不可 unpublish),號碼判斷屬於不可逆決定,發之前確認比發之後補救便宜。
2. **dogfood repo 的安裝副本用 `node bin/cli.mjs update` 重新蓋章比手動 sed 可靠**:一次同時更新兩支 hook 的 FW_VERSION、CLAUDE.md marker 版本、skill 內容,不會漏。本次驗證 marker 從 `v0.10.1 lang=zh-TW` 正確變 `v0.11.0 lang=zh-TW`。
3. 新加的覆蓋點名機制在此次 update 正確保持沉默(marker 版本 0.10.1 ≠ VERSION 0.11.0 → 不判定),驗證了「限同版本同語言才判定」的設計沒有誤報。
