# B2 示範影片:hook 四格插畫影片生成完成,直式沿用橫式

**TL;DR**:上個 session 畫好 hook 四格的首尾幀，等 Kai 確認畫風與報價。這次 Kai 定案：畫風維持咖啡金屬色調、直式短影片沿用橫式素材(不另畫 9:16)。生成前先讓子代理只挑錯審一遍首尾幀，修掉 H2、H4 會讓影片變形的問題，再用 Google Flow 生成四支 hook 影片;H2、H4 依 Kai 要求重生一次。共用 63 點，四支都逐格檢查過，組成 14 秒的無聲串接預覽。

## 關鍵發現

1. **Flow 影片按秒計價**:Omni 1.2 Flash 720p 每秒 3 點，長度 3–8 秒可調;出圖、改圖 0 點。上次「約 120 點」是照每支 8 秒估的，照旁白長度(4/3/3/4 秒)只要 42 點。因此 DECISIONS 裡直式「另生一套多 96 點」的理由也改正成約 42 點;不另生的主因是構圖會出框、角色要再對一次(見 DECISIONS 2026-11-11 首條)。
2. **生成前審首尾幀值得做**:子代理抓到兩個會讓影片硬變形的問題——H2 角色在首尾幀之間轉了 180 度;H4 尾幀憑空多出十幾張便利貼，記錄器還少了一片蓋子。兩者都用 Flow 改圖(0 點)修好再生成。審查原文：`docs/plans/demo-video.review-claude-subagent.md`。審查提到的「比例 1.95:1」只出在桌面的預覽檔,Flow 內原圖是 16:9。
3. **提示詞擋不住路徑本身的衝突**:H4 卡片從背上的記錄器飛到左邊軟木板，路徑必經頭部;寫明「沿畫面上緣、不經臉前」後，飛過臉前的時間從約半秒降到約 0.25 秒，但沒消失。要根治得改站位(重畫該格)。H2 則靠「全程側面、沒發現洞、不轉身不舉手」修好。
4. **首尾幀構圖相同時，提示詞寫固定鏡頭**:分鏡原本要求 H1 推近、H4 拉遠，但首尾幀是同一構圖，硬要模型動鏡頭會和影格衝突;改成後製數位縮放。
