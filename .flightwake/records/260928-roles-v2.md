## 關鍵發現(重要性排序)

1. **有座位的角色不能有原生副本**:r3 原設計「任何角色都產生原生定義」在下游 dry-run 被發現會讓 pm/tech-lead 在
   本地衍生 `fw-coder` 自己寫程式(Claude Code 依 description 自動委派),繞過寫/審分工 → 改為只產生待命角色
   (DECISIONS 2026-09-28;該團隊產物 24 → 12 檔)。教訓:dry-run 要在真實團隊上看,暫存 fixture 看不出分工漏洞。
2. **Codex 原生待命角色的前提是精確路徑信任**:上輪「叫不出來」的根因是 repo 未以精確路徑受信任,且 dotted `-c`
   寫法把引號留進 key(TRAPS `codex-project-trust-exact-path`,confirmed)。Orca 管過的 repo 通常已受信任
   (worker-start 會自動寫入,TRAPS `orca-worker-start-writes-codex-trust`,probable),但 worktree 路徑各算各的。
3. **TOML 多一個未知欄位,整個角色靜默消失**(TRAPS `codex-agent-toml-unknown-field-drops-role`,confirmed)→ 產生器只寫三欄。
4. **description 不會自動觸發委派**;座位區塊改寫成明確派工規則(「符合何時叫 → 那個角色做,不是你;叫不出來照實說」),
   下游 pm 被問 T04 OAuth 時主動排入 security 待命審查。
5. **CI 的 state-fresh 在自己的 repo 抓到自己**:連續 4 個 commit 沒收尾就推 → 擋下。框架在按設計運作;
   多 commit 的實作段落中途就該 record,不要等到最後。
